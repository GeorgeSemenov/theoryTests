# Области видимости
Какая область видимости у var, let const?

- Глобальная - переменные объявленные с помощью ключевого слова var вне функций и блоков доступны везде в коде программы и становятся полями глобального объекта window (не работает на let const)
```js
var puk = 1;
console.log(window.puk) // 1
let kek = 2;
console.log(window.kek) // undefined
```
- Блочная - область внутри {} (if,for, while ...) (работает только с переменными let и const)
```js
if(true){
	const kek = "puk";
}
console.log(kek) // reference error
```
- Функциональная(локальная) - переменные объявленные внутри функции доступны только внутри этой функции, переменные объявленные через var имеют локальную или глобальную область видимости.
```js
console.log(puk); // reference error в локальной области функции поэтому доступа нет.
function kek() {
	if(true){
		var puk = 'puk';
		const kek = 'kek';
	}
	console.log(puk) // puk
	console.log(kek) // reference error
}
  
kek();
```


Способы объявления
- var может иметь функциональную или глобальную область видимости, переменные объявленные таким образом игнорируют блочные ограничения, обладает всплытием (hoisting) - можно обращаться до объявления со значением undefined
```js
console.log(puk) // undefnied, до объявления - это называется hoisting
var puk = 1;
```
- let и const переменные имеют  блочную область видимости, подпадают под действие temporal dead zone, это значит, что они всплывают, но находятся в TDZ пока их не объявят и поэтому обращаться к ним нельзя
```js
console.log(kek); // Reference error
let kek = 'kek';
```
Какие есть два способа обращения к var-переменной, объявленной вне фукнций?
```js
var globalVar = "hello";
// Способ 1: прямое обращение по имени
console.log(globalVar); // "hello"
// Способ 2: через глобальный объект
console.log(window.globalVar); // "hello" (в браузере) и только если переменная обяъвлена глобально области видимости (т.е. не в функции а в корне)
console.log(global.globalVar); // "hello" (в Node.js)
```
Как объявить переменную в глобальной области видимости?

| Способ                              | Описание                                      |
| ----------------------------------- | --------------------------------------------- |
| **Вне любых функций**               | Объявить переменную на верхнем уровне файла   |
| **В браузере: явно через `window`** | `window.myVar = 123`                          |
| **`let`/`const` на верхнем уровне** | В модулях — не становятся свойствами `window` |

```javascript
// Способ 1: объявление на верхнем уровне
var globalA = 1;        // становится свойством window
let globalB = 2;        // НЕ становится свойством window (в модулях)
const globalC = 3;      // НЕ становится свойством window
// Способ 2: явное присвоение свойству window
window.myGlobal = 42;
// В Node.js
global.myGlobal = 42;
```

# Всплытие и Temporal Dead Zone
Что такое всплытие (hoisting) в рамках JS?
> всплытие это механизм JS, который поднимает объявления переменных и функций в верх. Это значит, что если они объявлены то к ним можно обращаться в любом месте без возможности получить ошибку reference error. Важно поднимается только объявление переменных, инициализация же не поднимается.
```js
console.log(varA) // undefined
console.log(letA) // reference error эта переменная обяъвлена но не имеет hoisting
console.log(isNotDefinedVariable); // reference error эту переменную вообще не объявили.

var varA = 10;
let letA = 20;
```
Всплывает ли var?
	Да, и сразу инициируются значением undefined
Всплывают ли let и const?
	да, но не инициируются и попадают в temporal dead zone, поэтому к ним обращаться нельзя.
Что такое Temporal Dead Zone (TDZ) и когда она возникает?
> temporal dead zone (TDZ) - это интервал между фактической областью видимости и объявлением переменной. Обращение к переменной в TDZ вызовет ошибку reference error

Почему попытка обратиться к переменной, объявленной через let или const, до её объявления вызывает ошибку?
	Потому что переменная будет находиться в TDZ

# TDZ на практике
```js
// Что будет выведено при выполнении кода?
let a = 1;

function b() {
  console.log(a); // reference error, потому что a, которая объявлена в этой области видимости (в функции) всплыла, но попала в TDZ, поэтому обращаться к ней нельзя, и при этом это уже не та "a" которая была объявлена в начале кода
  let a = 2;
}

b();
console.log(a); // 1
```

# Symbol
Что такое Symbol в JavaScript и зачем он нужен?
> symbol - примитив, который всегда уникален.
```js
const sym1 = Symbol();
const sym2 = Symbol();
console.log(sym1 === sym2) // false
```

|Задача|Как помогает Symbol|
|---|---|
|Создание **уникальных ключей** для объектов|Исключает случайные коллизии имён свойств|
|Создание **скрытых свойств**|Свойства-символы не перечисляются в циклах `for...in`|
|**Расширение встроенных протоколов**|Общеизвестные символы позволяют переопределять поведение объектов (`Symbol.iterator`, `Symbol.toStringTag`)|
Равны ли два символа с одинаковыми описаниями? Symbol('a') === Symbol('a')
	Нет, символ всегда уникален.
Что такое общеизвестные символы? Зачем они нужны?
> общеизвестные символы (well known symbols) - встроенные символы, которые позволяют переопределять стандартное поведение объектов.

Самый известный символ это iterator
```js
const range = {
    start: 0,
    end: 3,
    
    [Symbol.iterator]() {
        let current = this.start;
        const end = this.end;
        
        return {
            next() {
                if (current <= end) {
                    return { value: current++, done: false };
                }
                return { done: true };
            }
        };
    }
};
console.log([...range]); // [0, 1, 2, 3]
```

# Optional Chaining
Что такое optional chaining и зачем он нужен?
> optional chaining - оператор, который позволяет обращаться к вложенным свойствам объекта не вызывая ошибки, если промежуточное свойство равно undefined
```js
const user = {};
console.log(user.address?.street) // undefined
```
Есть переменная a, она либо `[1]` либо `undefined`. Как получить нулевой элемент массива, если он существует с помощью optional chaining?
```js
a?.[0]
```
Есть переменная b, она либо `() => console.log(1)`, либо `undefined`. Как вызвать функцию, если она существует с помощью optional chaining? 
```js
b?.()
```

# Математические операторы

```js
// ** - возведение в степень
```

Как работает оператор `%` и чему равно `10 % 3`?

```js
console.log((2+3)*4) // 20
```

	ответ 2,5 JS делает вычисление с плавающей точкой.

# Условия и null-safe оператор
Чем отличаются операторы &&, || и ?? по принципу работы?

| Оператор | Название           | Возвращает                                                     | Условие остановки                      |
| -------- | ------------------ | -------------------------------------------------------------- | -------------------------------------- |
| `&&`     | Логическое И       | **Первое ложное** значение (falsy), либо последнее истинное    | когда встречает `false`                |
| `\|`     | Логическое ИЛИ     | **Первое истинное** значение (truthy), либо последнее ложное   | когда встречает `true`                 |
| `??`     | Nullish coalescing | **Правое**, если левое `null` или `undefined`, иначе **левое** | когда левое не `null` и не `undefined` |
```js
const puk = "loh";
const kek = "pidr";
console.log(undefined ?? puk )// loh
console.log(kek ?? puk )// pidr
```
Что вернёт выражение true && 'ok' и почему?
	Вернёт 'ok' потому что возвращает первое ложное значение, либо последнее истинное.
Что вернёт выражение false || 'fallback' и почему?
	Вернёт 'fallback' потому что возвращает первое истинное значение, либо последнее.
Чем поведение 0 || 5 отличается от 0 ?? 5?
```js
console.log(0 || 5) // 5 , потому что 0 это falsy значение
console.log(0 ?? 5) // 0 , потому ?? в выражении нет null или undefiend, значит будет возвращено левое значение.
```
Почему выражение null && 'test' возвращает null, а не 'test'?
	Потому что null яляется ложным значением (falsy)

# Объявление функций
Что такое function expression? А function declaration?
> Function expression - функция определяется внутри выражения, например, переменной. Есть hoisting, однако переменная в которую записывается функция попадает в TDZ. может быть анонимной
> Function declaration - функция  определяется как отдельная конструкция. есть hoisting нет TDZ. Можно вызывать до определения и функция будет корректно (в отличае от переменных с var, там при вызове до определения будет undefined)
```js
// function expression
const kek = function puk { console.log("puk kek")} // именованная функция
const loh = function { console.log("puk kek")} // анонимная функция

// function declaration
pidr() // "я электросамокатчик" можно вызвать до инициализации
function pidr(){ console.log("я электросамокатчик")}
```

Всплывает ли function expression? А function declaration?
	Ответ на оба вопроса - да. Только fucntion expression будет ещё находится в TDZ.
Что такое new Function expression? Как объявить функцию с помощью этого выражения?
```js
// new Function - способ создать функцию из строки кода во время выполнения (runtime)
const sum = new Function ("a", "b", "return a + b");
console.log(sum(2,3,))// 5
```

# Spread/Rest операторы
Что такое spread-оператор? На какие сущности его можно применить? Что он позволяет делать?
> spread оператор - разворачивает итерируемую сущность на отельные элементы.
```ts
// массивы
const arr = [1,2]
const rar = [...arr]
// объекты
const obj = {a:1, b:2};
const job = {...obj}
// строки
const str = "kek";
const char = [...str] // [ 'k', 'e', 'k' ]
// Set
const mySet = new Set([1,2,3,3,4,4,4,4,4,5]);
const arr = [...mySet];// [1,2,3,4,5]
// Map
const myMap= new Map[['id','2'],['age','32']]
const arr = [...myMap] // [['id','2'],['age','32']]
```

Что такое rest-оператор? Что он позволяет делать с параметрами?
> rest оператор - собирает оставшиеся элементы в массив
```js
// собрать аргументы функции в массив
function kek(numb1,...numbers){return numb1 +  numbers.reduce((acc,next)=>acc+next,0)	}

// собрать элементы в подмассив (деструктуризация)
const [a,b,c,...numb] = [1,2,3,4,5,6,7,8]
console.log(a); // 1
console.log(numb); // [4,5,6,7,8]

// собрать элементы в подобъект (деструктуризация)
const {id, ...obj} = {id: 1, name:'bob', orientation: "gay"}
console.log(obj); // {name:'bob', orientation: "gay"}
```
Чем spread-оператор отличается от rest-оператора?
	spread оператор разбивает объект на части, используется при создании новых объектов, массивов ...
	rest оператор - собирает объект из частей, и.
Чем запись `{ id: 1, ...user }` отличается от записи `{ ...user, id: 1 }`?
	Порядком свойств в объекте. Нужно учитывать, что при конфликте ключей приоритет имеет то свойство, которое появляется последним.
```js
const obj = {kek:"puk", id : 1};
const loh = {id:2, ... kek }; // {kek:"puk", id:1}
const loh = { ... kek, id:2 }; // {kek:"puk", id:2}
```

# Деструктуризация
Что такое деструктуризация?
> Дестрктуризация - конструкция, которая позволяет извлечь значения из массивов и объектов в переменные.
```js
//Как деструктуризировать массив? Приведи пример
const [a,b] = [1,2]; // a = 1, b =2 ;
// деструктураизация объекта
const {c,d} = {c:3, d:4} // c = 3, d = 4;
```
Как переименовать поле при деструктуризации?
```js
const {propertyName: newPropertyName} = {propertyName:"propertyValue"};// newPropertyName = propertyValue
```
Как указать значение по умолчанию при деструктуризации?
```js
const {field : newName = "defaultValue", c} = {c: 25} // newName = "defaultValue"
```
Как деструктуризировать объект внутри деструктуризации объекта (несколько вложенностей)? Приведи пример
```js
const {a, inner:{loh}} = {a: 25, inner:{loh:"kek"}} // a = 25, loh = "kek"
```

# Генераторы
Что такое функция-генератор? Чем она отличается от остальных функций?
Как объявить генератор? Что возвращается при вызове yield?
> Функция генератор - функция, которая может приостанавливать своё выполнение и возобновлять, сохраняя своё состояние между вызовами.
```js

// функция гейнератор создаётся с помощью function declaration

	yield 1; // возвращает значение через yield
	yield 2; 
	return 3; // завершает с помощью return
}

const puk = generator(); // возвращает итератор
console.log(puk.next()) // {value: 1, done:false}
console.log(puk.next()) // {value: 2, done:false}
console.log(puk.next()) // {value: 3, done:true}

// поддерживается также function expression
// Также yield позволяет осуществлять двухстороннюю связь
const myGen = function* pukGenerator(){
	const response = yield 'a',// yield может возвращать то что передаётся в next()
	console.log("you've got ", response);
	yield 'b'
	// return не обязателен, после последнего yuild он тоже вернёт значение, просто оно будет undefined
}

const loh = pukGenerator();
console.log(loh.next("pidr")) // {value:'a', done:false}
```


# Итераторы
Что такое итератор в рамках JS?
Что делает метод `next()` и что он возвращает?
> Итератор, это объект, который даёт последовательный доступ к элементам коллекции, с помощью метода next(). Каждый вызов next возвращает следующий элемент коллекции

Как сделать объект итерируемым?
```js
const obj={
	from : 1,
	to : 10
	[Symbol.iterator]() {
		let current = this.from;
		let end = this.to;
		return {
			next(){
				if(current > end) return {done: true}
				return {value :current++ , done:false}
			}
		}
	}
}
```
Как работает цикл `for...of` с итерируемыми объектами?
1. Вызывает у объекта метод `[Symbol.iterator]()`, получая итератор
2. Повторно вызывает `next()` на итераторе
3. Присваивает `value` переменной (пока `done: false`)
4. Останавливается, когда `done: true`

Как связаны генераторы и итераторы в JavaScript?
	Генератор возвращает итерируемый объект с методом next 

# Практика с итераторами

```ts
// С помощью генератора реализуй итератор, который будет возвращать по очереди ключ объекта, значение объекта, ключ объекта и т.д.
```

# Геттеры, сеттеры

# Цепочка Promise
```js

  .catch((err) => err + '_3') // ничего, ошибка уже была обработана во втором аргументе then, который шёл перед catch
  .then((val) => val + '_4', (val) => val + '_8') // error_2_4 ошибки нет, поэтому выполнится первый аргумент then
  .finally((val) => val + '_5') // ничего не изменится, finally возвращает промис со значением, которое у него было до finally
  .finally((val) => console.log(val)) // выведет undefined, finally не принимает аргументов, следовательно val будет равно unefiend
  .then((val) => console.log(val)) // выведеться error_2_4

// ответ - выведеться: 
// undefiend 
// error_2_4
```
Ключевые моменты : 
- then всегда возвращает Promise 
- finally не принимает аргументов
- finally тоже возвращает промис с тем же значением, которое было у промиса до выполнения finally

# Event Loop
Что такое Event Loop?
> Event loop (событийная шина) - механизм, который позволяет в однопоточном выполнении кода JS выполнять асинхронные операции.

Event Loop это механизм предоставляемый JavaScript или он предоставляется чем-то другим?
	Event Loop предоставляется окружением - браузером или node.js 
Что такое микрозадача? Что такое макрозадача? В какой последовательности они выполняются?
- Микрозадача - микрозадача это чаще всего асинхронная операция, сохраняется в стэке микрозадач.
- Макрозадача - Тяжеловестная операция, в eventloop - она выполняется по одной, после каждого выполнения макрозадачи происходит проверка и выполнения всего списка микро задач.
Перечисли как минимум 3 микрозадачи
	1) обработка промиса.than.catch.finally 
	2) **`queueMicrotask(callback)`** - специальный метод, который поставить колбек в очередь микрозадач
	3) **`MutationObserver(callback)`** - метод, который следит за имзенениями dom дерева, при изменении запускает callback, который сразу помещается в очередь микрозадач
Перечисли как минимум 3 макрозадачи
	1)setTimout, setInterval
	2)обработка DOM событий (клик, скролл и т.д.)
	3)requesAnimationFrame
Одинаково ли работает Event Loop в Node.js и в браузере?
	Нет. Основный принцип выполнения похож - синхронный код -> список микрозадач -> одна макрозада 
	Но есть отличия:

| Аспект                 | Браузер                                            | Node.js                                                       |
| ---------------------- | -------------------------------------------------- | ------------------------------------------------------------- |
| **Фазы цикла**         | Одна простая очередь макрозадач                    | Несколько фаз (timers, pending, idle, poll, check, close)     |
| **Приоритеты**         | `setTimeout` и `setInterval` в одной очереди       | `setImmediate` vs `setTimeout`                                |
| **Микрозадачи**        | Выполняются между макрозадачами, перед рендерингом | Между фазами                                                  |
| **`process.nextTick`** | Нет                                                | Очередь nextTick с более высоким приоритетом, чем микрозадачи |
Зависит ли перерисовка страницы от Event Loop? Объясни ответ
	Да, перерисовка выполняется после завершения всех микрозадач, но перед выполнением макрозадачи. Поэтому обилие микрозадач может привести к зависанию браузера.
Что такое Call Stack? Что такое Web APIs? Что такое Callback Queue?
- call stack - стукрутра в которой хранятся контексты выполнения функций, в ней можно увидеть последовательность выполениня функций, которые выполняются по принципу обоймы (LIFO)
- Web APIs (или worker APIs, Node APIs) - асинхронные операции представляемые окружением (setTimeout, fetch, DOM события и т.д.)
- Callback Queue - очередь макрозадач
Расскажи какой путь по Event Loop проходит функция setTimeout(() => console.log('Hi'), 100), чтобы вывести Hi в консоль
1) setTimeour попадает в call stack
2) браузер / среда регистирурет выполнение колбека из setTimeout через 100 мс с помощью webAPI, колбек сохраняется
3) call stack освобождается
4) через 100мс колбек попадате в marcrotask queue (callback queue) 
5) event loop проверяет пуст ли call stack, если не пуст, то высвобождает(выполняет все функции), иначе переходит к следующему шагу
6) event loop берёт колбэк из очереди макрозадач (callback queue) и помещяет в call stack
7) колбэк берётся из call stack и выполняется
8) колбэк высвобождается из call stack

# XMLHttpRequest
Почему XMLHttpRequest очень редко применяется в современных приложениях?
> XMLHttpReques - встроенный в браузер интерфейс (JS API) который позволяет отправлять на сервер запросы и получать ответы без перезагрузки страницы. В современных приложениях обычно используют fetch и промисы, они проще.

| Причина                             | Пояснение                                                                                          |
| ----------------------------------- | -------------------------------------------------------------------------------------------------- |
| **Устаревший, громоздкий API**      | Событийно-ориентированный, многословный, требует проверки `readyState` . Fetch API проще и чище    |
| **Нет нативной поддержки промисов** | Работает на колбэках → «callback hell»                                                             |
| **Плохая обработка ошибок**         | Ошибки сети ловятся, но HTTP-ошибки (404, 500) не попадают в `onerror`, их нужно проверять вручную |
Как отправить запрос с помощью XMLHttpRequest?
Как обработать результат запроса с помощью XMLHttpRequest?
Как обработать ошибку с помощью XMLHttpRequest?
```js
const xhr = new XMLHttpRequest();
xhr.open('GET', "lol.kek.ru/posts",true)// true - значит асинхронно
xhr.setRequestHeader("content-type","application/json");
// обработка результата
xhr.onload = function(){
	if(xhr.status>=200 && xhr.status<300){
		// При успешном ответе
		const data = JSON.parse(xhr.responseText)	
	 }

// обработка ошибок
```

Есть ли в XMLHttpRequest какой-то функционал, который не предоставляется fetch?
	Да, вот отличия XMLHttpRequest от fetch:
	1) возможность делать синхронные запросы xhr.open('GET',url,false) - блокирует выполнение дальнейшего кода, пока не выполнится запрос.
	2) Есть встроенный таймаут запроса xhr.timout = 300; 
	3) Есть отслеживание прогресса : xhr.onprogress

# Контексты
Какой вид функций (стрелочная или обычная) берёт контекст в момент вызова?
	Обычная функция берёт контекст в момент вызова.
```js
const obj = {
	name: 'gay'
	sayName: function(){console.log(`my name is ${this.name}`)}	;
}
const sayName = obj.sayName;
obj.sayName();// my name is gay
sayName(); // my name is undefined

function sayThis(){
	console.log(this)
}
sayThis(); // window или undefined если включён strict 
```
Какой вид функций (стрелочная или обычная) берёт контекст в момент объявления?
	Стрелочная функция берёт контекст в момент объявления. Важно понимать - стрелочная функция берёт this из внешней функции, а не из объекта в котором она создана.
```js
const obj = {
	name: "gaysha", 
	sayName : ()=>console.log(this.name) // this = undefined в момент объявления
	sayYouNameMotherFucker: function(){
		return ()=>console.log(this.name) // this берётся у внешней функции, поэтому name будет gaysh
	}
}

obj.sayName() // undefined
const sayName = obj.sayYouNameMotherFucker();
sayName() // gaysha
```

# bind/call/apply
Что делают методы bind call и apply?
```js
// bind создаёт новую функцию, this которой привязан к указанному объекту

const obj = {kek: "kek"};
function puk(arg1, arg2){console.log(`arg1 = ${arg1}, ${this.kek}, arg2=${arg2}`)};
puk(); // undefined;
const bindedPuk = puk.bind(obj,'arg1')
bindedPuk('arg2'); // arg1 = arg1, kek, arg2=arg2

// call и apply вызывают функцию сразу, привязывая this функции к указанному объекту, разница лишь в том, что call принимает аргументы для функции через запияту, а apply в виде массива

puk.apply(obj,['arg1','arg2'])// arg1 = arg1, kek, arg2=arg2
puk.call(obj,'arg1','arg2')// arg1 = arg1, kek, arg2=arg2
```
Можно ли вызвать bind call или apply на стрелочные функции?
	Вызвать можно, но это ничего не изменит. this стрелочной функции определяется при объявлении и переопределить его с помощью этих методов нельзя.
Что будет если два раза вызвать bind на функции? 
	bind может изменить this только один раз, вторая попытка переопределить this будет проигнорирована.
```js
// 4. Что выведется в консоль и почему?
function square() {
  console.log(this.width * this.height)
}

square.bind({ width: 16, height: 16 })() // 256, потому что this был заменён на объект 

console.log(Math.min.apply(null, [5, 2, 6])) // 2, для функции Math.min не важно чему равен this, поэтому этот вызов эквивалентен Math.min(5,2,6)
```

# Strict mode
Что такое strict mode? Какие есть два способа его включить?
> strict mode - режим включающий более строгую проверку на ошибки.
	Есть два способа включения режима strict mode:
	1) в начале скрипта прописать 'use strict' - режим будет работать для всего скрипта (файла)
	2) В начале тела функции прописать 'use strict' (function () {'use strict'}) - режим будет работать только для этой функции.

Что будет если написать `a = 2` со включенным strict mode?
	В строгом режиме объявление переменных является обязательным условием, в противном случае будет ошибка "Reference error". Вне строгого режима переменная без объявления автоматически получает глобальную область видимости.
Как strict mode влияет на область видимости функций?
	Функции объявленные внутри блоков if / for / while не поднимаются в область видимости внешней функции и остаются видны только внутри этого блока.
```js
// не строгий режим
if(true){
	function pidr (){console.log('kek,puk')}
}
pidr(); // kek, puk

'use strict'
if(true){
	function loh(){console.log('puk,kek')}
}
loh(); // reference error loh is not defined
```
Как strict mode влияет на работу с контекстами?
```js
// глобальный this
function kek {console.log(this)}
kek() // window

'use strict'
function puk {console.log(this)}
puk() // undefined

// bind/call/apply если передать null/undefined - остаётся null/undefined
function kek {console.log(this)}
kek().apply(null) // в нестрогом режиме this = null будет заменён на this = window

'use strict'
function puk {console.log(this)}
puk().apply(null) // undefined


```

# Конструктор
Что происходит при вызове функции с ключевым словом new? Что будет возвращено когда произойдёт вызов?
	При вызове функции с оператором new происодят следующие шаги:
	1) Создаётся пустой объект.
	2) Устанавливается прототип для объекта Object.setPrototype(newObject, Constructor.prototype)
	3) this функции привязывается к объекту
	4) Выполняется тело функции.
	5) Возвращаемое значение
		1) Если функция не возвращает явно объект/примитив, то возвращается this. 
		2) Если же функция возвращает явно примитив, то будет возвращён this а примитив проигнорируется.
		3) Если же функция возвращает явно какой-то объект, то будет возвращён этот объект а this проигнорируется.
```js
function User (name,age){
	this.name = name;
	this.age = age;
}

const user = new User('loh',12); // {name: 'loh', age:12}
```
На что ссылается this внутри функции-конструктора?
	this внутри конструктора ссылается на экземпляр создаваемого объекта.
```js
function puk(pidr,loh){
	this.pidr = pidr;
	this.loh = loh
	
	console.log(this);
}

const kek = new puk('pidr','loh'); // {pidr:'pidr',loh:'loh'}
```

# Наследование
Объясни, как работает наследование в JS. Что такое прототип? Может ли прототип наследовать прототип?
	1) Наследование - объекты могут наследовать свойства от других объектов. 
	2) Прототип - свойство объекта, которое содержит ссылку на объект родителя. Прототип представляет из себя скрытое свойство \[\[Prototype]] , доступное через __proto__ или через Object.getPrototypeOf(obj) ) Если происходит обращение к свойству объекта, которое он не содержит, то поиск этого свойства продолжается в цепочке прототипов, проверяя в ближайшем прототипе, если там нет, то идут по ссылке прототипа в прототипе.
	3) прототип может быть у прототипа. Цепочка прототипов может быть любой длины.
К какой сущности ведёт каждая цепочка прототипов?

|Объект|Прототип|Конец цепочки|
|---|---|---|
|**Обычный объект `{}`**|`Object.prototype` → `null`|`null`|
|**Массив `[]`**|`Array.prototype` → `Object.prototype` → `null`|`null`|
|**Функция**|`Function.prototype` → `Object.prototype` → `null`|`null`|
|**Строка-обёртка (`new String`)**|`String.prototype` → `Object.prototype` → `null`|`null`|
|**Объект с `null` прототипом**|`null`|`null` (сразу)|
|**Класс / функция-конструктор**|`Function.prototype` → `Object.prototype` → `null`|`null`|

Чем `.__proto__` отличается от `.prototype`?

| Свойство         | Где существует                                        | Что делает                                                       |
| ---------------- | ----------------------------------------------------- | ---------------------------------------------------------------- |
| **`.__proto__`** | В **каждом объекте** (кроме `Object.create(null)`)    | Ссылка на прототип (`[[Prototype]]`)                             |
| **`.prototype`** | Только у **функций** и **классов** (кроме стрелочных) | Объект, который станет прототипом экземпляров при вызове с `new` |
```js
function User(name) {
    this.name = name;
}
User.prototype.sayHi = function() { console.log(`Hi, ${this.name}`); };
const user = new User("Alice");
console.log(user.__proto__ === User.prototype);        // true
console.log(User.prototype.__proto__ === Object.prototype); // true
console.log(User.prototype.constructor === User);      // true
// У обычного объекта нет .prototype
const obj = {};
console.log(obj.prototype); // undefined
// Но .__proto__ есть
console.log(obj.__proto__ === Object.prototype); // true
```

# Новый метод для массива
Реализуй метод groupBy для массива, который будет пробегаться по всем объектам в массиве и группировать их по укзаанному ключу. Пример использования ниже
```js
const users = [
  { name: 'Oleg', group: 'User' },
  { name: 'Nikita', group: 'User' },
  { name: 'Danil', group: 'Admin' },
  { name: 'Nikolay', group: 'Superadmin' },
  { name: 'Stas', group: 'Admin' },

users.groupBy('group') // должно вернуть объект ниже

{
  User: [
    { name: 'Oleg', group: 'User' },
    { name: 'Nikita', group: 'User' },
  ],
  Admin: [
    { name: 'Danil', group: 'Admin' },
    { name: 'Stas', group: 'Admin' },
  ],
  Superadmin: [
    { name: 'Nikolay', group: 'User' },
  ],
}

// реализация
Array.prototype.groupBy = function(property){
	return this.reduce((acc,nxt)=>{
		if(!acc[nxt[property]]) acc[nxt[property]] = []
		acc[nxt[property]].push(nxt)
		return acc
	},{})
}
```

# Классы
Что такое класс в программировании? Какие три составляющих есть у классов?
> Класс это шаблон для создания объектов.
	Класс состоит из трёх компонентов:
	1) конструктор - специальный метод для инициализации нового объекта.
	2) методы - обычные методы, как у обычного объекта.
	3) поля - данные хранящиеся в объекте.
```js
class User{
	// поля
	name,
	age
	// конструктор
	constructor(name, age){this.name = name, this.age = age}
	// методы
	// чтобы обратиться к полю класса в нутри метода класса нужно использовать this
	greed(){console.log(`my name is ${this.name}. Age is ${this.age}`)}
}

const user = new User('Greg', 33)
user.greed(); // my name is Greg. Age is 33
```
Чем являются классы в JS? Это самостоятельная сущность, или надстройка над чем-то уже существующим?
	Классы в JS это синтаксический сахар над прототипным наследованием существующем в JS с самого начала.
```js
// аналог класса но через функцию с прототипным наследванием

	// поля
	this.name = name;
	this.age = age;
	// в роли конструктора выступает тело функции
	
	// методы
	this.greed = function(){console.log(`my name is ${this.name}. Age is ${this.age}`)}
}

const user = new User('Greg', 33)
user.greed(); // my name is Greg. Age is 33
```
Что в классах делает метод constructor(), и в какой момент он вызывается?
	конструктор инициализирует объект в момент создания (когда класс вызывается с ключевым словом new)

# WebWorker
Что такое WebWorker и зачем он нужен?
> webworker - инструмент, позволяющий запускать вычисления в фоновом режиме, не замораживая  страницу для пользователя (пользователь сохраняет возможность взаимодействовать со станицей)

Почему JS считается однопоточным, несмотря на наличие воркеров?
	JS всегда однопоточный. Воркеры создают отдельные изолированные потоки, которые
	- не имеют доступа к DOM, 
	- не блокируют основной поток, 
	- общаются с основным потоком через сообщения.
Как создать новый вебворкер?
```js
// main.js
const worker = new Worker('worker.js')

// ------ //
// файл воркера worker.js
self.onmessage = function (e){ // воркер получает данные через объект 'e'
	console.log('get data = ', e.data)
	const result = e.data *2 ; // что то делаем с данными
	self.postMessage(result); // отправляем в основной поток обработанные данные.
}
```
Как отправить в воркер новое сообщение? Как получить из него сообщение?
	Использовать метод postMessage
```js
worker.postMessage(42) // Передали значение 42 вебворкеру
```
Может ли Web Worker обращаться к DOM? Почему?
	Нет не может, потому что воркер работает в изолированном контексте .
Какие данные можно передавать между потоком и Web Worker?
	Примитивы, объекты и массивы.
	Нельзя передавать DOM элементы, объекты с прототипами (при перемещении цепочка прототипов разрушается)

# SharedWorker
Что такое SharedWorker и чем он отличается от обычного Web Worker?
> sharedWorker - web worker который может быть общим для нескольких окон , вкладок или iframe одного источника (origin), в отличае от обычного web worker, который привязан к одному скрипту/окну
Как создать новый SharedWorker? Как подключиться к уже существующему из нескольких окон браузера?
```js
if(window.SharedWorker){
	const sharedW = new SharedWorker("shared-worker.js");
	sharedW.port.start() // начинаем общение через старт
	
	sharedW.port.onmessage = function(e){
		console.log('worker got ' + e.data);
	}
	
	sharedW.port.postMessage("hello from tab")
}else{
	console.log("SharedWorker не поддерижвается");
}
```
Как осуществляется обмен сообщениями между SharedWorker и подключёнными скриптами?
```js
// shared-worker.js
const connections = [];
self.onconnect = (event) => {
    const port = event.ports[0];
    connections.push(port);
    
    port.onmessage = (e) => {
        console.log("Из порта:", e.data);
        
        // Ответить ТОЛЬКО этому порту
        port.postMessage("Received: " + e.data);
        
        // Отправить ВСЕМ портам
        connections.forEach(conn => conn.postMessage("Broadcast: " + e.data));
    };
    
    port.start();  // заполнить для порта
};
```
Можно ли SharedWorker обращаться к DOM? Почему?
	Нет, также как обычный воркер - sharedWorker изолирован от DOM, по причине безопасности.
Как завершить работу SharedWorker?
	sharedWorker завершает работу автоматически когда:
	1) Все порты закрыты (port.close() )
	2) Последняя вкладка с подключением закрыта.
Как отследить новое подключение внутри SharedWorker?
	Использовать метод onconnect см пример выше
Как отследить закрытие подключения внутри SharedWorker?
```js
// Уведомляем воркер при закрытии вкладки
window.addEventListener('beforeunload', () => {
    port.postMessage({ command: 'closing' });
});
```

# Счётчик вкладок
Сделай SharedWorker, который будет содержать в себе счётчик совершённых к нему подключений. При новом подключении счётчик должен прибавляться и рассылать во все подключения сообщение о том, что произошло новое подключение. Это сообщение должно выводиться в консоль во всех подключенных вкладках. Код основного потока пиши под комментарием main.js, код воркера - под комментарием sharedWorker.js
```js
// main.js - тут основной код
const worker = new SharedWorker('sharedWorker.js');
worker.port.start();

worker.port.onmessage = (e) => {
    console.log(e.data);
};

// Сообщаем воркеру, что это новое подключение (опционально, для явного уведомления)
worker.port.postMessage({ type: 'newConnection' });

// sharedWorker.js - тут код воркера
let connectionCount = 0;
const ports = new Set();

self.onconnect = (event) => {
    const port = event.ports[0];
    ports.add(port);
    
    // Увеличиваем счётчик подключений
    connectionCount++;
    
    // Отправляем приветственное сообщение новому порту
    port.postMessage(`[Connected] Новое подключение! Всего подключений: ${connectionCount}`);
    
    // Рассылаем всем портам сообщение о новом подключении
    ports.forEach(p => {
        p.postMessage(`[Broadcast] Подключился новый клиент! Всего активных подключений: ${connectionCount}`);
    });
    
    port.onmessage = (e) => {
        // Можно обрабатывать дополнительные сообщения от портов
        console.log('Сообщение от порта:', e.data);
    };
    
    port.onclose = () => {
        ports.delete(port);
    };
    
    port.start();
};
```

# IndexedDB
Что такое IndexedDB и для чего он используется? Чем отличается от localStorage?
> indexedDB - встроенная в браузер не реляционная база данных, созданная для хранения больши объёмов структурированных данных

| Характеристика    | localStorage  | IndexedDB                                                      |
| ----------------- | ------------- | -------------------------------------------------------------- |
| **Объём**         | 5–10 МБ       | Обычно > 50 МБ, может быть до сотен МБ или ГБ                  |
| **Асинхронность** | ❌ Синхронный  | ✅ Асинхронный (не блокирует поток)                             |
| **Типы данных**   | Только строки | Строки, числа, даты, объекты, массивы, Blob, File, ArrayBuffer |
| **Индексы**       | ❌ Нет         | ✅ Да (можно искать по не-ключевым полям)                       |
| **Транзакции**    | ❌ Нет         | ✅ Да                                                           |
| **Сложность**     | Простой       | Более сложный, требует колбэков или Promise-прокси             |
Как создать базу данных и объектное хранилище (object store) в IndexedDB?
```js
// открытие, создание базы данных (версия 1)
const openRequest = indexedDB.open("myDB",1)

openRequest.onupgradeneeded = (event)=>{
	const db = event.target.result;
	
	// создаём объектное хранилище с ключом ID (автоинкремент)
	const userStore = db.createObjectStore("users",{
		keyPath: 'id', // поле, используемое как ключ
		autoincrement: true
	})
	
	// создаём индексы для поиска по другим полям.
	userStore.createIndex('byName','name',{unique:false}); // имя индекса byName, поиск будет вестись по полю 'name'
	userStore.createIndex('byAge','age',{unique:false});
}
```
Как работать с транзакциями в IndexedDB и зачем они нужны?
> Транзакции - группа операций, которые выполняются как единое целое. Либо все выполняются успешно, либо все откатываются к исходному состоянию.
Зачем нужны :
1) атомарность - нет полумер, либо все выполнятся, либо ни одна (не будет так, что деньги списались с одного счёта, а на другом не добавились)
2) Изоляция - другие транзакции не знают друг о друге.

# ServiceWorker
Что такое ServiceWorker и чем он отличается от других воркеров?
>  ServiceWorker - вебворкер, работающий в фоновом режиме и выступающем в роли прокси сервером между браузером и сетью. Может работать даже при закрытой вкладке.

Как создать новый сервис-воркер?
```js
// main.js
if('serviceWorker' in navigator){
	navigator.serviceWorker.register('sw.js').then((registration)=>{
		console.log("ServiceWorker зарегистрирован ", registration.scope)
	}).catch((err)=>{console.log("ошибка при регситрации ", err)})
}

// sw.js
self.addEventListener('install',event=>console.log('serviceWorker установлен'))
self.addEventListener('activate',event=>console.log('serviceWorker активирован'))
```
В чём основная цель применения ServiceWorker?
	1) Оффлайн режим - продолжать работу без интернета 
	2) Ускорение загрузки - отдача ресурсов из кэша
	3) push-уведомления - получение уведомлений даже при закрытой вкладке.
	4) фоновая синхронизация - отправка данных при восстановлении сети.
Какие основные состояния есть у сервис воркеров? Опиши каждое
	- parsed - файл скачан и начинает парситься
	- installing - происходит установка (событие install)
	- installied/waiting - Установлен, ждёт активации (если есть старый акттивный сервис воркер)
	- activating - активация, обработка события "active"
	- activated - активирован, может контролировать страницы (fetch  перехватывается)
	- redundant - бесполезное состояние
Как перехватить запрос на сервер с помощью сервис воркера?
```js
// sw.js
self.addEventListener("fetch", (e)=>{
	console.log("произошёл перехват запроса ", e.request.url)
	e.respondWith(fetch(e.request))// обычный овтет с сервера
})
```
Как переопределить ответ на запрос через сервис воркер?
```js
// sw.js
self.addEventListener('fetch', e=>{
	e.respondWith(
		new Response('<h1>New Response</h1>',{
			headers:{'Content-Type' : 'text/html'}
		})
	)
})
```
Как сохранить данные в кеш с помощью сервис-воркера?
```js
const CACHE_NAME = "my-cache-v1";
const urlsToCache = ['/','/style.css','/script.js']

self.addEventListener('install',e=>{
	e.waitUntil(
		caches.open(CACHE_NAME).then(cache=>cache.addAll(urlsToCache))
	)
})

// при перехвате отдаём из кэша.
self.addEventListener('fetch',e=>{
	e.respondWith(
		caches.match(e.request).then(response=>response || fetch(e.request)
	)
})
```
Какие локальные хранилища можно использовать внутри сервис-воркера?
	cacheStorage - для кеширования
	IndexedDB - для больших структурированных данных

	Все остальные хрнилища - недостпуны:
		localStorage/SessionStorage - синхронные поэтому недоступны
		Cookie - нельзя получить доступ через document.cookie, но можно получить через заголовки.

# Сборка мусора
Что такое сборщик мусора (garbage collector) в JS и зачем он нужен?
> Сборщик мусора (garbage collector) - механизм который очищает память от объектов на которые не ведёт ни одной ссылки. GC нужен для того, чтобы предотвратить утечку памяти.

Какие типы значений считаются "живыми" и "мертвыми" для сборщика мусора?
	Живые (которые не удаляются): 
		- глобальные объекты (window в браузере и global в node.js)
		- Все объекты доступные из корней по цепочке ссылок. Под корнями понимаются следующие сущности:
			- глобальные объекты (window)
			- стэк вызовов
			- активные замыкания
			- DOM узлы
		- локальные переменные в выполняющихся функциях
	Объекты на которые не ведёт ни одна ссылка называются мёртвыми.
Что такое подсчёт ссылок (reference counting) и как он работает?
> Подсчёт ссылок - это алгоритм, который подсчитывает сколько ссылок ведёт указывает на объект. Если это значение становится равным 0 то объект удаляется.
```js
let a = {kek:'puk'} // одна ссылка
let b = a // две ссылки.
a = null; // одна ссылка
b = null; // ссылок больше нет, объект удаляется
```
Что такое маркировка и зачистка (mark-and-sweep) и как этот алгоритм работает в JS?
> маркировка - процесс нахождения корней и всех доступных объектов из них.
> зачистка - все немаркированные объекты удаляются из памяти.
```js
function puk(){
	const a = {};	const b = {}; // объекты промаркинованы и существуют
}
// после завершения функции объекты теряют маркировку и будут удалены.
```
Могут ли возникнуть циклические ссылки и как современные движки с ними справляются?
	Да, циклические ссылки возможны.
```js
function kek(){
	const a = {ref:''}; const b = {ref:''};
	a.ref = b;
	b.ref = a;
}
// два объекта ссылаются друг на друга, получается циклическая ссылка, хотя из корней к ним доступа нет. 
// Чтобы удалить эти объекты существуют механизм mark-and-sweep. Если из корней доступа до объекта нет - он подлежит удалению.
```
Когда вызывается Garbadge Collector?
	GC запускается автоматически, время от времени, но когда он запустится наверняка - невозможно.

# Set, WeakSet
Что такое Set и чем он отличается от обычного массива?
> Set - набор уникальных значений по набору, нет доступа по индексу.
Как создать новый Set и добавить в него элементы?
```js
const set = new Set()
set.add(1);
set.add(5);
set.add(5);// игнорируется потому что значение 5 уже есть.
console.log(set) // Set(2) { 1, 5 }
const set2 = new Set([1,5,5]) // Set(2) {1,5}

// Как проверить, есть ли элемент в Set, и как удалить его?
set.has(5) // true такой элемент есть
set.has(2) // false двойки тут нет.

set.delete(5) // true элемент есть, он будет удалён
set.delete(2) // false такого элемента нет.

// Как узнать размер Set?
console.log(set.size)

// Можно ли перебрать элементы Set и в каком порядке они возвращаются?
// Перебрать можно, вощращаться элементы будут в порядке добавления
const set3 = new Set([1,2,34,5,])
for(s of set3){console.log(s)}// 1 ,2 ,34, 5
set3.forEach(s=>console.log(s))// 1, 2, 34, 5

```

Что такое WeakSet и чем он отличается от Set?
> WeakSet - коллекция уникальных объектов (не примитивов) которые хранятся по "слабой" ссылке
> Слабая ссылка (weak reference) - такая ссылка, которая не мешает сборщику мусора удалить объект, если на него ссылаются только слабые ссылки.
Какие типы значений можно хранить в WeakSet?
	Только объекты
Как добавить элемент в WeakSet и как проверить его наличие?
```js
const ws = new WeakSet();
const obj = {kek:'puk'};

ws.add(obj);
ws.has(obj); // true 
ws.add(obj); // ws не изменится, потому что ссылка на этот объект уже есть
ws.delete(obj); // true ссылка на объект obj удалена из ws
```
Можно ли перебрать элементы WeakSet и почему?
	Нет. У weakSet нет методов forEach, keys, values. Нет свойства size;
Когда объекты в WeakSet удаляются сборщиком мусора?
	Как только нет других сильных ссылок на объект .

# Map, WeakMap
Что такое Map и чем он отличается от обычного объекта?
> Map - коллекция "ключ - значение", где ключом может быть любой тип данных, в отличае от object, где ключом мог быть только строка или символ.

Почему Map стоит использовать вместо объектов для структур типа хешмап?
	потому что можно использовать ключи любых типов, и Map гарантирует порядок данных, в отличии от object.
Как создать новый Map и добавить в него элементы?
```js

const obj2 = {puk : 'kek'}

map.set('kek','pu')
map.set(obj1,obj2) // по ключу obj1 будет доступен obj2

const map2 = new Map([
	[obj1,'val1']
	[obj2,'val2']
])

// Как проверить, есть ли ключ в Map, и как удалить его?
map.has(obj1) // true 
map.has(obj2) // false такого ключа нет, есть только значение
map.delete(obj1) // true удалено
map.delete(obj2) // false нечего удалять

// Как узнать размер Map?
console.log(map.size)// 1 (потому что ключ obj1 удалили)

// Можно ли перебрать элементы Map и в каком порядке они возвращаются?
for (const [key, value] of map ){
	console.log(`${key} => ${value}`)
}
map.forEach((value, key)=>console.log(`${key} => ${value}`) )
map.keys() // Выведет: [Map Iterator] { 'kek' }
map.values() // Выведет: [Map Iterator] { 'puk' }
for (let [key, value] of fruits.entries()) { 
	console.log(`${key} стоит ${value} рублей`); 
}
```
Что такое WeakMap и чем он отличается от Map?
> weakMap - коллекция ключ-значение со слабыми ссылками.

Какие типы ключей можно использовать в WeakMap?
	Только объекты (не примитивы), null тоже нельзя.
Как добавить элемент в WeakMap и как проверить его наличие?
```js
const wm = new WeakMap();
const key = {puk:'kek'}
wm.set(key,'secret')
wm.has(key) // true
wm.get(key) // 'secret'
wm.delete(key) // true
```
Можно ли перебрать элементы WeakMap и почему?
	Нельзя, потому что нет forEach, keys, values, entries
	Это сделано по причине того, что сборщик мусора может в любой момент удалить объект, на который указывает слабая ссылка. Невозможно контролировать колличество таких объектов.
Когда объекты в WeakMap удаляются сборщиком мусора?
	Как только на  объект перестают указывать сильные(не слабые) ссылки - объект удаляется.
# Жизненный цикл страницы

Как вывести пользователю предупреждение "вы точно хотите со страницы?"
	**Событие `beforeunload` + возврат непустой строки** (формат для браузера). Современные браузеры показывают стандартное сообщение, а кастомный текст игнорируют (по соображениям безопасности).
```js
window.addEventListener('beforeunload', (event) => {
    // Сообщение (браузер покажет своё, но значение должно быть непустым)
    event.preventDefault();              // стандартная активация диалога
    event.returnValue = '';              // устаревший, но обязательный приём
    return '';                           // для старых браузеров
});
```
- `preventDefault()` сам по себе **не останавливает** уход → он только **включает механизм показа диалога** подтверждения    
- Без вызова `preventDefault()` диалог **не покажется**, даже если есть `returnValue`
- Кастомный текст **игнорируется** (кроме некоторых старых браузеров) — браузер показывает своё сообщение

# Shadow DOM
Что такое Shadow DOM и зачем он используется?
> shadow DOM - встроенный в вебкомпонент механизм инкапсуляции DOM.
> Используется для :
> 1) изоляции стилей (внутренние стили не влияют на остальной документ)
> 2) сокрытия внутренней реализации компонента

Чем Shadow DOM отличается от обычного DOM?
	1) CSS свойства обычного и теневого DOM - не пересекаются.
	2) Внутренняя структура сокрыта от основного DOM (у обычного DOM все элементы видны глобално (можно получить доступ через document.querySelector и т.д.))
	3) Есть чёткая граница инкапсуляции (shadow boundary)
Какие режимы существуют при создании shadow root и чем они отличаются?
```js
// Режим "open" — можно получить доступ через .shadowRoot
const openRoot = element.attachShadow({ mode: 'open' });

// Режим "closed" — .shadowRoot вернёт null (нельзя получить извне)
const closedRoot = element.attachShadow({ mode: 'closed' });
```
Как получить доступ к элементам внутри shadow root из внешнего JS?
```js
// Если shadow root создан с mode: 'open'

// Для mode: 'closed' — доступ извне невозможен
```

```js
            <span class="value">${this.count}</span>
            <button class="plus">+</button>
        `;

        shadow.appendChild(container);
```

# Tree-shaking и lazy-loading
Что такое Tree-shaking? Нужно ли его настраивать в современных бандлерах? От чего зависит, будет ли три-шейкаться библиотека?
> tree-shaking - процесс удаления неиспользуемого кода из итоговой бандла при сборке. В соверменных банлдерах (webpack, vite ... ) он включен в production по умолчанию, настраивать не нужно.
	
	Библиотека будет шейкать, если используются import/export (вместо require) и если включен в package.json sideEffects: false - значит, что импорт сторонней библиотеки не вызывает побочных действий.
	
Что такое лези-лоадинг? Зачем он нужен?
> lazy-loading - техника при которой ресурсы загружаются тогда, когда они нужны, а не в момент загрузки страницы. Он нужен, чтобы уменьшить размер бандла, ускорить загрузку и сэкономить трафик.

Как реализовать lazy-loading крупной библиотеки при открытии конкретной страницы сайта?
	Использовать динамический импорт.
```js
button.addEventListener('click',()=>{
	const {heavyFunction} = await import('heavy-lib');
	heavyFunction()
})
```
Чем динамический импорт отличается от обычного?
	1) Динамический выполняется после какого-то события, а статический на момент на этапе компиляции
	2) Динамический - можно использовать внутрий функция, статический - нельзя.
	3) Динамический может использовать динамические пути, статический - только статические.

# Тики анимации
Что такое `requestAnimationFrame` и для чего он используется?
> requestAnimationFrame - метод браузера, который планирует выполнение функции, перед следующей перерисовкой экрана (подстраивается под частоту обновления экрана, обычно 60 раз в секунду). Используется для создания плавных анимаций.
Чем `requestAnimationFrame` отличается от `setTimeout` и `setInterval` при анимации?
	1) синхронизирован с частотой обновления экрана
	2) Останавливается, если вкладка не активна
	3) Автоматически адаптируется к нагрузке (может начать пропускать кадры)
	4) вызывается строго перед перерисовкой
Как правильно использовать `requestAnimationFrame` для плавной анимации?
```js
const element = document.getElementById('myElement');
let start = null;
let duration = 2000; // 2 секунды

function animate(timestamp){
	if(!start) start = timestamp; // Если функция выполняется в первый раз, то запоминаем момент, когда она вызывается.
	const progress = timestamp - start; // сколько длится выполнение функции
	const percentage = Math.min(progress/duration,1)
	
	element.style.transform = `translateX(${percentage * 100}px)`; // собственно создание анимации. (элемент потихоньку будет двигаться влево)
	
	if(percentage < 100){
		requestAnimationFrame(animate) // рекурсивный вызов animate, за счёт этого создаётся плавность анимациию В animate передаётся timestamp
	}	
}
requestAnimationFrame(animate); // Первый вызов animate. В animate передаётся timestamp
```
Что произойдет, если вызывать `requestAnimationFrame` рекурсивно внутри его же callback?
	будет бесконечная анимация. Колбэк будет вызываться перед каждым кадром.
Как `requestAnimationFrame` ведет себя при сворачивании или переключении вкладки браузера?
	Останавливается.
Как отменить запланированный вызов `requestAnimationFrame`?
```js
const animID = requestAnimationFrame(animate);
cancelAnimationFrame(animID);
```
Почему использование `requestAnimationFrame` предпочтительнее для анимации в современных браузерах?
	1) Плавные анимации, синхронизированные с частотой обновления экрана.
	2) Оптимизация нагрузки, при свёрнутой вкладке анимация прекращается + браузер может подключить GPU и частично разгрузить CPU.
	3) Высокая производительность - за одно обновление экрана может быть несколько raf

# Clipboard API
Что такое Clipboard API и для чего он используется в браузере?

Чем отличаются методы `writeText` и `readText`?

```js
	const text = await navigator.clipboard.readText();
```

# Proposals
Что такое JS Proposals? Что такое TC39?
> Proposals - официальные предложения по добавлению новых возможностей в язык JS
> TC39 (technical committe 39) - комитет, который управляет стандартом JS (ECMAScript), состоит из представителей компаний Mozilla, google, apple, microsoft и другие заинетерсованные

Какие стадии пропозалов существуют?
0) stage 0 (strawman) - неофициальные предложения и идеи, пока что не представленные комитету.
1) stage 1 (proposal) - официальное предложение коммитету. Определяется проблема с примерным API  для решения.
2) stage 2 (Draft) - Первая черновая версия спецификации. Уже готово описание синтаксиса  и семантики на языке спецификации
3) stage 3 (Cadidate) - Финальная спецификация, готовая к реализации в движках . На этом этапе изминения вносятся только в случае критических проблем.
4) stage 4 (finished) - proposal прошёл все этапы, имеет несколько реализаций и готов стать частью стандарта ECMAScript
Что такое Temporal? Зачем его придумали?
> Temporal - новое API для работы с датами и временем. Призвано заменить устаревший Date

Что такое ShadowRealm? Зачем его придумали?
>ShadowRealm - proposal (находится на stage 3) дающий возможность создавать новый чистый контекст выполнения JS (realm). Представь - JS без доступа к DOM, глобальным переменным и прототипам. 
>Используется для изоляции потенциально опасного кода. Сейчас используют костыли наподобии iframe, но доступ к DOM всё равно сохраняется

# Виртуализация
Что такое Intersection Observer? Что он позволяет делать?
> intersection Observer - браузерный интерфейс, позволяющий отслеживать изменения пересечения одного элемента с другим (обычно вьюпорта и какого-нибудь контейнера на странице, аналог scroll) 
	Позволяет реализовать: 
	- бесконечную прокрутку, 
	- Ленивую загрузку изображений
	- узнавать - появился ли элемент в области видимости.

Чем отличается использование Intersection Observer от отслеживания прокрутки через события scroll?
	Тем что intersection Observer :
	- Асинхронный, выполняется после изменений в потоке рендера, не блокирует поток
	- Не требует расчётов, браузер сам сообщает о пересечении, но в этом и минус - нельзя задать логику вычислений.
Что такое виртуализация? Как она работает и как связана с Intersection Observer?
> виртуализация - техника при которой рендерятся только те элементы, которые видны в данный момент, а остальные удаляются из DOM и замещаются заглушками. Область видимости определяется с помощью intersection Observer

# Отслеживание изменения DOM
Что такое `Mutation Observer` и для чего он используется?
> mutation observer - браузерный API который отслеживает изменения в DOM 
> позволяет асинхронно реагировать на добавление/удаление узлов .

Какие типы изменений DOM можно отслеживать с помощью `Mutation Observer`?
	Виды отслеживаемы изменений:
	- attributes - отслеживает изменения аттрибутов (class, id, style и др)
	- childList- добавление / удаление непосредственных потомков (не распространяется на внуков).
	- characterData - изменение текста внутри элемента
	- subtree - отслеживание внутри всего поддерева (этим данный метод и отличается от childList)
	- attributeOldValue / characterDataOldValue - сохранять старое значение атрибута/текста
	- attributeFilter - массив имён атрибутов, отслеживать только выбранные 'class', 'style'

# WASM
Что такое WASM? Как это связано с JS?
> **WebAssembly (WASM)** это низкоуровневое, переносимое бинарное представление кода, которое может выполняться в современных браузерах с производительностью, близкой к нативным приложениям
	Связь с JavaScript основана на принципе кооперации, а не замены. Они разработаны как взаимодополняющие технологии:
	- JavaScript используется для высокоуровневой логики, манипуляций с DOM и UI;
	- WebAssembly берет на себя вычислительно-интенсивные задачи, требующие максимальной производительности (игры, графика, видео/аудио-кодеки).

	Это означает, что в одном приложении вы можете вызывать код WASM из JS и наоборот
	
Как интегрировать WASM-модуль в JS-код?
	Самый эффективный способ — использовать метод `WebAssembly.instantiateStreaming()`. Он напрямую принимает Promise от `fetch()` и компилирует/инстанцирует модуль в один шаг, работая с потоком байткода напрямую
```js
// 1. Функции, которые мы хотим передать в модуль WASM (опционально иллюстрирует импорт)
const importObject = {
  // Имена модуля и функции должны совпадать с описанными в WASM
  env: { 
    log: (arg) => console.log("WASM says: " + arg) 
  }
};

// 2. Загрузка, компиляция и инстанцирование модуля.
//    Функция fetch получает файл .wasm, instantiateStreaming компилирует его.
WebAssembly.instantiateStreaming(fetch('module.wasm'), importObject)
  .then(result => {
      // 3. result.instance — это инстанс WASM-модуля.
      //    result.instance.exports — объект со всеми экспортированными функциями.
      const wasmExports = result.instance.exports;
      
      // 4. Вызов функции, экспортированной из WASM.
      if (wasmExports.main) {
          wasmExports.main();
      }
  })
  .catch(console.error);
```
